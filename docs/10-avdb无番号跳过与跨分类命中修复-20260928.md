## 二、根因 A：无番号的欧美帖被误判 skipped（dl_id 612）

### 症状

`avdb_watch.py` 的 `adopt()` 原判定：

```python
if not number and not manual:
    → skipped('记录无番号(手动下载/测试记录)')
```

`skipped` 是**终态**，`seen` 表里一行落定就再也不重试 → 欧美帖（avdb 的 article.number 常常为空）永久不接手。

### 修法

无番号时先取候选名：

```python
src.name_candidates(row['resource_name'] or row['title'])
```

- **只有连候选名都凑不出来**才 `skipped`；
- 有候选名则跳过 `skipped`，把它交给入库侧按 115 落点目录认领。

配套 `import_api.adopt_resolve()`：

```python
can_claim = bool(num) or manual or bool(extra)
loose    = bool(num) or bool(extra)
```

`save_path` 精确找不到时，遍历 `avdb_claim_roots(p, skip=save_path)` **强制 `loose_only=True`** 跨分区兜底；
仍失败时若 `not num and (manual or extra)`：

```python
return {'waiting': True, 'error': '115 落点暂无待认领目录 (%s)' % ('手动提交, 等 115 下载落地' if manual else '欧美帖无番号, 等 115 下载落地')}
```

→ 记 **waiting**（可重试）而不是终态 missing。

新增 `avdb_claim_roots(p, skip='', ttl=600)`：模块级 `_AVDB_ROOTS_CACHE`，
枚举 `/sehuatang/AVDB` 下所有装片的叶子目录，10 分钟缓存。实测枚举结果：
`亚洲有码/未分类、未分区/未分类、亚洲无码/无码破解、磁力/magnet、中文字幕/有码高清`。

改后实测日志：

```

[adopt] id=612 (无番号) → 按落点目录认领: /sehuatang/AVDB/中文字幕/无码高清/[中文字幕]Bangbus.20.08.19.Blake.Blossom.4k (loose-number)
```

## 四、根因 C：MDC 产物跨分类命中误判（612 第二次修，本轮最大改动）

### 症状

612 第一次重放后 task `f1bc365db16b` 以 `step=nfo` + 「MDC 未刮削或元数据不完整…请用油猴脚本补充元数据」结束，
面板挂「待补元数据」。**但元数据其实已经刮好了**：

```
/mnt/g/srtm/已刮削/欧美/无码B 系列/BangBus.20.08.19/
  BangBus.20.08.19-C.nfo   # 完整剧情/演员/年份/类型
  poster.jpg  thumb.jpg  fanart.jpg  *.zh-CN.ass   # 18:27–18:30 写入
```

### 根因

`_wait_mdc_scrape()` 只扫 `category_target_root(category_of_local_dir(local_dir))` = `已刮削/AV`，
而 MDCng 自己按片名把欧美片分流进 `已刮削/欧美`；且 `_extract_fanhao_candidates()` 对欧美片名返回**空**（没有标准番号）
→ 白等到超时 → 误判「元数据不完整」。

### 改动（`import_api.py`）

1. **`_loose_dir_cands(local_dir)`** —— 去掉 `[标签]`/序号后按 `. 空格 _ -` 切，取前 3、2 段（含数字且 ≥8 字符）：
   `Bangbus.20.08.19.Blake.Blossom.4k` → `['Bangbus.20.08', 'Bangbus.20']`。
2. **`_mdc_name_cands(local_dir)`** —— 标准番号候选优先；否则**只用宽松候选里最长的 k=3 那条**。
   > 注释里记录了实测原因：k=2 的 `Blacked.16` 会把 `Blacked.16.11.x` 错配到 `Blacked.16.08.18`。
3. **`_find_mdc_output_across(local_dir)`** —— 按候选名扫全部分类根，命中且 nfo+图片齐全才返回；
   **凑不出候选名就直接放弃**（不靠 recent-min 瞎猜）。
4. **`_mdc_out_matches_local(local_dir, out_dir)`** —— 命中后核名：`_fanhao_key(base).startswith(key) or key in base`。
5. **`_wait_mdc_scrape()`** —— 新增 `alt_roots`（其余分类根）+ `x_cands`；循环里 **60s 起**（`ALL_ROOTS_AFTER=60`）
   加「②b 跨分类兜底」分支，命中即返回
   `True, 'MDCng 刮削完成并移入(跨分类): …'` 并打 WARNING。超时后的复议也并扫 `roots + alt_roots`（用 `x_cands or cands`）。
6. **调用侧（3.6 步）** ——
   ```python
   cross_cat = bool(mdc_dir and not mdc_dir.startswith(_own + os.sep))
   ```
   `_wait_mdc_scrape` 失败时再补一道 `_find_mdc_output_across` + `_mdc_out_matches_local`；
   中文标题规则改为 `elif mdc_ok and not _mdc_title_has_chinese(meta_dir) and not cross_cat:`
   —— **跨分类命中不触发「无中文标题即删元数据」**（欧美片标题本就多为英文）。
   `cross_cat = False` 提前到健康检查之前定义。

### 为什么 60s 才扫跨分类

目录 walk 成本实测：`已刮削/AV` 681 目录 2.73s、丝袜 452 目录 1.86s、欧美 45 目录 0.17s、
FC2 24 目录 0.10s、里番 62 目录 0.33s、`_trash_国产` 3 目录 0.01s。
MDCng 正常命中都在自己分类内，跨分类是少数派 —— 若从第 1 秒就扫，每 5s 轮询要白付 2.5s。

### 实测验证

`/tmp/verify_across.py`：612 → `BangBus.20.08.19`（核名 True）、609 → `REAL-988`、608 → `HJBB-202` 全部正确命中。
610/611 的宽松候选 `Blacked.16.11` 在同系列内有歧义（walk 顺序先撞 `Blacked.16.11.06`），
**只影响日志文字、不影响数据**。
