# 03 · 使用方法

## 一、油猴脚本（浏览器端）

### 1.1 安装

1. 浏览器安装 Tampermonkey（油猴）插件
2. 打开油猴管理面板 → 「实用工具」→「导入」→ 选择 `src/userscript/sehuatang_import.user.js`
3. 编辑脚本，修改头部配置：

```javascript
// ===== 可配置 =====
const API_BASE = 'http://<SERVER_IP>:5081';   // ← 改成你的 import-api 地址
const POLL_MS = 6000;                          // 任务状态轮询间隔（毫秒）
// ==================
```

4. 保存并启用。

> 脚本 `@match` 已覆盖 `sehuatang.net` / `sehuatang.org` 的 http/https。

### 1.2 在帖子页入库

打开色花堂任意帖子页，页面左上角出现**磁力导航面板**：

| 控件 | 功能 |
|---|---|
| 每个链接按钮 🚀 | 单条入库：弹出入库类型选择（已入库/排队中的链接会直接提示，不再重复提交） |
| 类型选择「影片」 | 番号类单部电影：推→等→清小文件→strm→MDC 刮削→Emby 刷新→预热 |
| 类型选择「剧集」 | 非番号合集/剧集：推→等→重命名 thread_xxx_S01E01→strm→油猴补充元数据 |
| ⚡ 批量入库 | 一次提交本页全部（或勾选）磁力/ed2k：默认类型整批共用，行内可单独改成「番/剧」，先 👁 预览再 🚀 提交，进度显示在面板头部徽章（v1.11.0） |
| ✏️ 手动输入 | 手动输入磁力/ed2k 链接入库（支持多条，提交到当前 thread） |
| 📤 元数据补充 | 从帖子页提取标题/简介/图片，上传服务器生成 Emby 海报与简介 |
| 📋 任务监控页 | 一键跳转 `/tasks` 状态页 |
| 📌 标题行 | 显示链接数量与批量进度徽章（`⚡完成/总数`）；右侧 `—`/`+` 折叠展开面板 |
| 拖动标题行 | 面板可拖到任意位置，落位记进油猴存储（刷新、翻页仍停在原地，越界自动收回画面内）；**双击标题行**复位到左上角 |

### 1.3 批量入库（⚡，v1.11.0）

帖子页磁力动辄几十条，逐条点效率太低。点工具条 **⚡ 批量** 打开批量面板：

1. **（可选）调类型**：顶部「默认类型」番号/非番号整批共用；个别链接要单独走另一种，点该行右侧的「番/剧」即可
2. **（可选）调分类**：顶部下拉选刮削分类（AV/FC2/丝袜/国产自拍/欧美/里番，会记住上次选择）；也可在粘贴的链接行尾写 `#分类key` 单独覆盖
3. **勾选**：默认全选；已提交过的行默认不勾选。快捷键：全选 / 全不选 / 反选 / **仅未在库**（v1.15.1：只勾 115 里还没有的，跳过 ✅在库 的行 —— 原来的「仅未提交」在刚打开面板时等价于全选，是个废按钮，已换掉）
> v1.15.0：每行右侧**直接显示库存徽章** ✅在库 / ❓不在库 / ⚠️未校验（与左上角面板同一口径），开弹窗就能看清哪条已经在 115 里，不用关掉弹窗回面板对照。
4. **👁 预览**：只做校验不建任务，先把无效行、重复行挑出来
5. **🚀 批量入库**：按类型分批提交（单批上限 100 条，超了自动切开），服务端逐条建任务并按队列执行

提交后**可以关掉面板继续浏览**：进度显示在标题行的 `⚡完成/总数` 徽章上，导航列表框内对应链接尾部显示 🕒（进行中）/ ✅（已入库）/ ❌（失败），鼠标悬停可看 task_id。超过 100 条时前端按类型自动分批提交，无需手工切。

> 批量入口只是把「逐条点 🚀」换成一次提交，落点、剧集模式、元数据目录与单条入库**完全一致**（同一个 `thread_<tid>`）。

### 1.4 元数据补充（📤）

- 抓取帖子标题、简介、图片（仅静态 jpg/png/webp/gif，排除小图标/表情包）
- **图片为用户手工点选**：候选图网格最多选 9 张，可 📌 标记海报、↑↓ 调整顺序、✕ 移除
- 上传保留原格式（gif 传 .gif、png 传 .png），自动生成 `poster.jpg` / `fanart.jpg` / `backdrop1.jpg`… 并触发 Emby 刷新 + 预热
- 标题清洗：自动去掉发布者/来源前缀、体积配额后缀、分区论坛后缀（不影响入库原始标题，面板中可手动编辑）

### 1.5 注意事项

- **剧集任务需等 `/tasks` 状态变为 `done`**（strm 阶段完成）后再点 📤 上传；仍在 wait/下载/整理中上传会失败
- 影片任务如果 MDC 刮削失败或元数据不完整，任务会提示「请在帖子页用油猴脚本补充元数据」

## 二、任务监控页（服务器端）

访问 `http://<SERVER_IP>:5081/tasks`：

| 功能 | 说明 |
|---|---|
| 任务列表 | 状态（queued/wait/video/strm/done/failed）+ 步骤 + 进度 |
| 详情 | 点击查看任务时间线、错误信息 |
| 🎬 MDC 重跑 | 影片任务一键重跑（rescrape）：从 115 源文件重建 strm + 刮削（含影片重命名环节） |
| #tid 跳转 | thread 号可点击，直达帖子页做油猴补充 |

> **一键入库首页**（`http://<SERVER_IP>:5081/`）也能直接手动批量入库：粘多行链接 → 选类型/分类 → 👁 预览 → 🚀 批量入库。
> 连点两次不会再发重：同一批链接 **60 秒内重复提交会被前端直接拦**（提示还差几秒，请求都不发）；
> 即使换个浏览器绕过，服务端也会按链接 hash 查重 —— 同链接已有 `queued/running` 任务就跳过这一条，
> 结果里回报 `dup_skipped` 和逐行原因。（2026-09-22：此前无任何防线，实测连点两次建了 28 条任务，
> 同链接两条任务并发互相删 115 离线任务，13 条白跑一轮还失败 1 条。）

## 三、入库 API 说明

所有接口返回 JSON。

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/import` | POST | 提交单条入库 `{thread_id, title, magnet/ed2k, kind, thread_url}` |
| `/api/import/batch` | POST | 批量入库 `{links: [..] 或 "一行一条", kind, category, thread_id, title, thread_url, dry_run}`（单批 ≤100 条）→ 返回 `{submitted, failed, skipped, dup_skipped, items[], duplicates[], errors[]}`；**`dup_skipped` = 同链接已有 queued/running 任务而被跳过的条数**（2026-09-22 防重） |
| `/api/import/list` | GET | 任务列表（分页） |
| `/api/import/status` | GET | 任务状态 `?task_id=` |
| `/api/import/history` | GET | 任务时间线 |
| `/api/import/rescrape` | POST | MDC 重跑 `{thread_id, kind:"mdc"}` |
| `/api/import/lookup` | POST | 库存反查 `{links: [磁链/ed2k…], title?, thread_id?, thread_url?, contexts?: [[文本…]…], single?}`（单批 ≤40 条）→ 逐条三态 `in/out/unknown` |
| `/api/metadata` | POST | 元数据补充（nfo/图片写入 + Emby 刷新） |
| `/health` | GET | 健康检查 |

### 示例：提交入库

```bash
curl -X POST http://<SERVER_IP>:5081/api/import \
  -H 'Content-Type: application/json' \
  -d '{
    "thread_id": "1234567",
    "title": "【原档】示例标题",
    "magnet": "magnet:?xt=urn:btih:xxxxxxxx",
    "kind": "fanhao",
    "thread_url": "https://sehuatang.net/thread-1234567-1-1.html"
  }'
```

### 示例：批量入库（面板 ⚡ 走的接口）

```bash
curl -X POST http://<SERVER_IP>:5081/api/import/batch \
  -H 'Content-Type: application/json' \
  -d '{
    "links": ["magnet:?xt=urn:btih:xxxx", "ed2k://|file|示例.avi|123456|yyyy|"],
    "kind": "fanhao",
    "category": "av",
    "thread_id": "1234567",
    "title": "【原档】示例标题",
    "thread_url": "https://sehuatang.net/thread-1234567-1-1.html",
    "dry_run": true
  }'
```

- `dry_run: true` 只回解析结果（`items` / `errors`），不建任务 —— 用于自检与面板预览
- `thread_id` 缺省时会从 `thread_url` 里抠 `thread-<id>` / `tid=<id>`，保证落点与单条入库一致
- 链接行尾可写 `#sw` 之类单独覆盖 `category`；同一链接重复出现会被记进 `errors` 并计为 `skipped`

### 示例：元数据补充

```bash
curl -X POST http://<SERVER_IP>:5081/api/metadata \
  -H 'Content-Type: application/json' \
  -d '{
    "thread_id": "1234567",
    "title": "示例标题",
    "desc": "帖子简介",
    "kind": "fanhao",
    "images": [{"name":"poster.jpg","data":"<base64>"}, ...]
  }'
```

### 示例：库存反查（导航面板的 ✅ / ❓ / ⚠️ 徽章）

打开帖子页后，导航面板每条链接右侧会显示一个小徽章，告诉这件东西**是不是已经在你的 115 里**，
省得重复入库。它走的是 `/api/import/lookup`：

```bash
curl -X POST http://<SERVER_IP>:5081/api/import/lookup \
  -H 'Content-Type: application/json' \
  -d '{"links": ["magnet:?xt=urn:btih:xxxx"], "title": "SNOS-403 授業中ですら… - 98堂",
       "thread_url": "https://www.sehuatang.net/thread-1234567-1-1.html", "single": true,
       "contexts": [["SNOS-403 授業中ですら…", "SNOS-403 授業中ですら… - 98堂"]]}'
```

- `links` 与 `contexts` **同序同长**（`contexts[i]` 是第 i 条磁链所在的页面文本，由近到远）。
  色花堂上裸磁链（没有 `&dn=`）的番号只存在于**页面正文**里，所以脚本会把磁链所在的 DOM 文本一并送来。
  每层已剔掉**本条磁链原文**（否则 40 位 btih 会混进番号候选），单层 ≤200 字符、总量超额整批丢弃。
- `single`：这一页**只有一条**链接时为 `true`，此时才允许拿页面标题兜底当番号来源
  （分片提交后最后一片可能只剩 1 条，所以由前端显式给，服务端不自己猜）。
- 老脚本（只送 `links`）行为完全不变。

响应（`items` 与入参**同序同长**，前端按索引回填）：

```json
{
  "items": [
    {"link": "magnet:?xt=urn:btih:xxxx", "link_hash": "xxxx",
     "fanhao": "SNOS-403", "src": "ctx",
     "state": "in", "checked": "ledger_fanhao"}
  ],
  "req_115": 0, "elapsed_ms": 5, "counts": {"in": 1, "out": 0, "unknown": 0},
  "ledger": {"f2done": 273, "done": 333}
}
```

`fanhao` 的来源记在 `src` 里：`ledger`（台账 hash→番号映射）/ `magnet`（链接自带 `&dn=`）/
`ctx`（页面上下文）/ `title`（页面标题，仅单链接页）。

三态的含义，以及每种情况的判定依据：

| 状态 | 徽章 | 含义 | 判定依据 |
|---|---|---|---|
| `in` | ✅在库（绿） | 这件东西已经在你的 115 里 | `checked=ledger`：入库台账里有这条 hash（**0 次 115 请求**）；`checked=ledger_fanhao`：台账里有这个**番号**（**0 次 115 请求**，按番号匹配，可能是另一条磁链推的 —— 同番号不同版本会一并算“在库”，故意如此）；`checked=115`：115 全盘搜索命中 |
| `out` | ❓不在库（灰） | 当前搜不到 | 115 搜索干净返回 0 条 —— **不等于确定没有**（搜索是模糊匹配，文件也可能被改名/挪走） |
| `unknown` | ⚠️未校验（黄） | 本次没查成 | `reason=no_fanhao` 链接里和页面文本里都没解析出番号 / `reason=mcp_down` 115 MCP 无响应 / `reason=ratelimit` 115 处于限频窗口 |

> ⚠️ **`unknown` 绝不显示成“不在库”**。115 MCP 一掉线就把整页标成“不在库”，会让人把已经入库的东西重复推一遍 ——
> 所以拿不准时宁可显示“未校验”，也不猜。

设计要点（改这个功能前先读）：

- **判定链（从上到下，先便宜后贵）**：① 台账里这条 hash 且没被删 → 直接 `in`（0 请求）
  ② 链接自带 `&dn=` → 番号 ③ 页面上下文 → 番号 ④ 页面标题（仅单链接页）→ 番号 ⑤ 番号命中台账 → `in`（0 请求）
  ⑥ 都不中才去 115 全盘搜索。**只有 ⑥ 会碰 115**，所以打开帖子页大多数时候是零请求。
- **`ledger` 与 `ledger_fanhao` 不是一回事**：前者是“这条磁链的内容入过库”（强证据），
  后者是“这个番号入过库，可能是另一条磁链推的”（与 115 实搜同一语义层级，故可互为缓存）。
- **跨条查重防呆（合集帖）**：同一段证据文本若供出 ≥2 条不同的 hash，该番号作废退回 ⚠️
  —— 一个帖子标题罩 12 条磁链时全部不采信，12 条各带各番号的则互不干扰。宁可 ⚠️，不要假 ✅。
- **搜索是模糊匹配**，`SNOS-400` 会把 `SNOS-403 / SNOS-406-U` 一并捞回来，所以命中结果要用
  `_fanhao_key()`（吃掉横线和前导零，`VRKM-01741` ≡ `VRKM1741`）二次校验，只认严格相等的。
- **番号必须带横线**：搜索词是 `SNOS-400` 这种形态；`SNOS400` 在 115 里搜不到任何东西。纯数字（如 `400`）是垃圾场，直接放弃。
- **缓存**：`in`/`out` 600 秒，`unknown` 180 秒；入库成功后（`save_task(status='done')`）会**只失效那一条**，
  不做全清 —— 全清会让下次打开帖子页重新打满 115。
- **限频护栏**：`_ratelimit_active()` 为真时**一个 115 请求都不发**，整批直接 `unknown/ratelimit`。
- **闸门**：115 MCP 不可用时返回 `unknown/mcp_down`，且**不落缓存**，恢复后自动重查。
- 前端另有开关：油猴脚本里的 `INV_ON`，置 `false` 即可关掉徽章（不用动服务端）。
- **徽章只有一个绘制入口 `invPaint()`（v1.15.0）**：左上角面板行与批量弹窗行共用同一个函数 —— 两处各写一遍，迟早会出现「面板说在库、弹窗说未校验」的自相矛盾。弹窗打开时会自己补查一次（`invRender()` 先画缓存 + `invQuery()` 补空缺）。
- **自查（v1.14.1）**：控制台每轮打一行 `[sht] 库存反查: N 条 | 115 请求 N 次 | Nms | … | 番号来源 {ctx:[…]}`；
  只要结果里有一条靠**页面文本**判出来（或一条都没抠出番号），后面还会多打一行
  `[sht] 诊断 · 送给服务端的页面文本 (由近到远)` —— 直接看它就知道「抠出来的番号对不对」
  「是真没有番号，还是爬错了 DOM 层」。

## 五、日常运维速查

```bash
# 重启入库服务（WSL 下的实际单元名是 sehuatang-import）
sudo systemctl restart sehuatang-import

# 查看入库日志
journalctl -u sehuatang-import -f

# 看一眼库存反查命中情况（面板打开帖子页时打的那行日志）
journalctl -u sehuatang-import -f | grep 库存反查

# 查看限频状态（云主机）
cat /opt/115push/ratelimit_state.json

# SmartStrm 容器
docker logs smartstrm --tail 50
```
