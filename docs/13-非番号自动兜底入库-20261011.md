# 13 · 非番号资源自动兜底入库（一文件一条目，条目名=文件名） — 2026-10-11

## 起因

用户方向：**「入库名字按照文件名字，然后 Emby 自动给图就行」**。
即：一个帖子里有几个视频，就进几条、各自用自己的文件名当条目名，不需要再去帖子页点 📤 上传元数据。

原来的行为：非番号/杂项资源在入库流程里**直接跳过 MDCng**，然后停在

```
MDC 未刮削或元数据不完整: 请在帖子页用油猴脚本补充元数据 (thread #3824718)…
```

也就是说，这类资源必须人工点 📤 才有一条记录，而且 📤 是**整帖级**的
（payload 只有 `{thread_id, title, desc, images}`，没有"选哪一条视频"字段），
`_find_emby_movie_dir()` 命中第一个目录就 return，一帖多视频时会把 3 个 strm
硬链接进**同一个目录**、共用一个目录名 → Emby 里 3 条同名同图。

## 改动（唯一文件 `src/server/import_api.py`）

备份：`src/server/.bak-20261011-105240-非番号自动兜底前/import_api.py`
（改前 374,185 B，md5 `f4fb66d8913ff98fd4aad75e3026ff69`）。

### 1. `_clean_entry_stem()`（:6353）— 清站标前缀

```python
_STEM_SITE_PREFIX_RE = re.compile(r'^(?:[A-Za-z0-9][A-Za-z0-9\-]{0,30}\.)+[A-Za-z]{2,10}@')
```

- 循环剥离多层站标：`WWW.98T.LA@nidekikibabe-2026-1.mp4` → `nidekikibabe-2026-1`
- `twojav.com@13dsvr01939_1_8k.mp4` → `13dsvr01939_1_8k`
- 同时去掉 `.strm/.mp4/...` 扩展名（`_STEM_VIDEO_EXT_RE`）

### 2. `_fallback_emby_movie_dirs_per_file()`（:6462）— 一文件一目录

遍历 `待看/<cat>/thread_<id>/*.strm`，**逐文件**在
`MANUAL_ROOT=/mnt/g/srtm/已刮削/杂项` 下建目录 `<清洗后的文件名>/`：

- 硬链接 strm 为 `<stem>.strm`（已存在则跳过，按 inode/大小判定）
- 写**目录同名 nfo**：`<stem>.nfo`（`_movie_nfo_xml(stem, '', thread_id)`，title = 文件名）
  —— 依据 `_ensure_dir_nfo:1027` 的根因：**没有目录同名 nfo，Emby 不把目录当电影单元、不分配 poster**
- **不写任何图片** → 缺图由 Emby 的 Image Capture 抽帧自动补（见 `docs/12`）
- 国产 `cn` 分类仍排除
- 返回 `(dirs, info)`，日志 `[metadata] 非番号自动兜底(一文件一目录): thread=… -> 杂项 N 条 per-file(link=…,existing=…,bad=…)`

### 3. 接进入库触发点（:2196）— 用 `skip_mdc` 划边界

`skip_mdc=True` 仅当 `norm_category(category)==MANUAL_CATEGORY`（杂项）或 `kind=='non_fanhao'`，
**正好就是"非番号/杂项"这一类**，因此用它当闸门：

```python
if skip_mdc:                     # 非番号/杂项：自动兜底，不再等 📤
    fb_dirs, fb_info = _fallback_emby_movie_dirs_per_file(thread_id, ttl, category)
    if fb_dirs:
        _trigger_emby_scan()     # 扫库广播
        time.sleep(8)
        for d in fb_dirs:        # 逐目录定向刷新（最多 3 次、间隔 4s）
            _refresh_emby_path(d, full=True)   # 缺主图自动带 AllowFfProcess → 抽帧
        save_task(..., status='done', step='scan',
                  msg='非番号自动入库完成: N 条(条目名=文件名) 定向刷新 M 条 → 缺图的由 Emby 抽帧自动补图')
        _start_prewarm(...)
        return
    # 兜底建不出目录 → 退回旧行为
save_task(..., step='nfo', msg='MDC 未刮削或元数据不完整: 请在帖子页用油猴脚本补充元数据 …')
```

**边界**：有番号但 MDC 刮削失败/不完整（`skip_mdc=False`）**保持旧行为**，
仍标「待补元数据」等 📤 —— 那是"刮错了/刮不到"，不是"根本不需要元数据"，
自动按文件名入库会把错番号固化下来。

## 影响面 / 注意

- **📤 变可选**：杂项/非番号资源现在无需人工介入；有番号 MDC 失败、剧集模式仍需 📤。
- **副作用（重放时观测到）**：115 因「任务已存在 → 删旧任务重推」会产生**同名重复文件**
  （本次 3 个文件在 115 目录里列成 5 项，多出 `-1`/`-2` 两条副本，约 +2.86GB）。
  本地 strm 仍是 3 个、Emby 仍是 3 条（strm 生成以 `thread` 目录为单元、按已有 strm 去重），
  只是 115 暂存区多占空间。属既有行为，与本次改动无关。
- **回滚**：把备份 `import_api.py` 覆盖回去 + `systemctl restart sehuatang-import` 即可。
- 服务日志在 `/var/log/import_api.log`（不是 journald）。
