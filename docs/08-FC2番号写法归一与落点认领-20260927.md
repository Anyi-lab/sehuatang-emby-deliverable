# 08 · FC2 番号写法归一 + 落点目录认领（2026-09-27）

> 触发：avdb 面板 #588–603 共 15 条报「**115 未找到 XXX 的落点目录**」，其中 12 条是 FC2。
> 结论：**片子全都在 115 上，一条没丢**；是「番号写法」与「115 目录名」不同源，匹配没认出。

avdb 面板（task monitor）里：

|---|---|---|---|
| 593 | `FC2-1680900` | 已提交/完成 scan | — （成功） |
| 594–603 | `FC2-4975283` 等 10 条 | 未找到 | `115 未找到 FC2-4975283 的落点目录 (avdb 记录 save_path=未分区/未分类)` |

## 二、根因（两条独立 bug，同源）

### 根因 1 · avdb 番号 ≠ 115 目录名

| avdb `download_log.number` | 115 上目录实际名 |
|---|---|
| `FC2-4975283` | `FC2PPV-4975283` |
| `FC2-2238344` | `FC2PPV-2238344-C` |
| `FC2-4571491` | `FC2-PPV-4571491` |
| `FC2-1680900`（成功那条） | `FC2-1680900` |

**为什么名字不同源**——avdb 官方 wiki（`更新日志.md` 20260316-2002）：

> 「修正 115 不使用 CID 时下载全部进入同目录的问题，现在**优先提取链接里的 `dn` 作为文件夹名**，
>  没有 dn 则使用磁力 `btih` 作为文件夹名称」

即 115 目录名 = **磁力自带的文件名**，avdb 只是照抄，**没有「目录命名模板」可配**（`设置-下载工具.md` 全文无此设置）。
而 avdb 自己记的 `number` 走的是它的「番号提取规则」（把 `PPV` 吞掉）。

匹配失败的直接证据（本地只读复现，改动前）：

```
same_number('FC2-4975283','FC2PPV-4975283')   = False
_loose_prefix('FC2-4975283','FC2PPV-4975283') = False
  _dir_key: fc24975283  vs  fc2ppv4975283   → 前缀不成立
对照 #593: same_number('FC2-1680900','FC2-1680900') = True   ← 目录名正好不带 PPV
```

旧 `number_key()` 对 `FC2PPV-2238344-C` 会拆成 `('FC','2')`（`^([A-Z]+)[-_]?(\d+)` 在 `FC2` 后遇到数字就断），
长度不足 4 直接判否 —— 所以连「含 PPV」的目录名也永远认不出来。

### 根因 2 · 分类会被判成 AV

`avdb_classify.RE_FC2` 旧值：`FC2[-_\s]?PPV|^FC2\d|^FC2$|FC2[-_]?PPV`
→ `FC2-4975283` 三个分支都不命中（`^FC2\d` 要求 FC2 后紧跟数字，这里跟的是连字符）
→ 落到兜底 `('av','无匹配规则, 默认 AV')`。
**即使认领成功，这批也会被塞进 AV 库而不是 FC2 库。**

## 三、改动（5 处，全部加法/收口，无删除逻辑）

| 文件 | 位置 | 改动 |
|---|---|---|
| `src/server/avdb_source.py` | `number_key()` 顶部 | 新增 `_RE_FC2_KEY = ^FC2(?:PPV)?(\d{3,8})`：`FC2` / `FC2PPV` / `FC2-PPV` 三种写法统一成 `('FC2PPV', 数字)` |
| `src/server/avdb_source.py` | 新增 `name_candidates()` | 把 avdb 记录的 `resource_name`（= 磁力/种子文件名 = 115 目录名）变成候选名，去掉 `.torrent` |
| `src/server/avdb_source.py` | `match_dir()` / `resolve()` | 新增 `extra_names=` 参数，候选名与番号**等效参与判同** |
| `src/server/import_api.py` | `_loose_prefix()` 首行 | 先过 `avdb_src.same_number()`（中央判同，已含 FC2 归一），再走原来的前缀式 |
| `src/server/import_api.py` | `claim_dir_resolve()` | 新增 `extra_names=`，`loose_only` 判定时也认候选名 |
| `src/server/import_api.py` | `adopt_resolve()` | 从记录取 `resource_name` → `avdb_src.name_candidates()` → 传给 `resolve()` 与 `claim_dir_resolve()` |
| `src/server/import_api.py` | `_FANHAO_FC2_RE` | `(FC2[-_]?(?:PPV[-_]?)?\d{4,8})`，能抠出 115 落地文件名里的 FC2 番号 |
| `src/server/avdb_classify.py` | `RE_FC2` | 追加 `^FC2[-_\s]?\d{4,8}$` 分支 |

**关键设计**：`resource_name` 是**唯一与 115 目录名同源**的字段（wiki 已证 115 用 dn 建目录），
所以它是比番号更可靠的锚点 —— 这也是这次不靠 avdb 任何设置就能修好的原因。

## 五点五、补图与 Emby 核验（本轮追加）

落点对了但**有 4 部没海报**：`FC2-4976598` `FC2-4972431` `FC2-4970939` `FC2-2238344`。
MDC 日志证据：

```
[FC2-2238344] 开始下载缩略图: https://fourhoi.com/fc2-ppv-2238344/cover-n.jpg
[FC2-2238344] 缩略图下载失败: error sending request, 尝试从备选链接下载...
```


## 七、遗留 / 未决

1. **avdb 侧没有「只给 FC2 落单独目录」的干净把手**：默认订阅规则（`设置 → 规则 → 订阅 → 默认订阅规则`）
   的 `save_path` 是**全局**的（现值 `{section}/{category}`），改了会影响所有订阅；per-订阅自定义目标管不住
   排行榜每天新建的订阅。若要真分流，得改排行榜订阅的落点策略（未做）。
2. **排行榜订阅里的内容类型可按需关闭**：那个「排行榜自动订阅」弹窗里的 `FC2` 按钮（= `SubscriptionRankingConfig.content_types`）关掉即可不再自动下 FC2。
