## 一、一句话结论

Emby 播不了 strm 的根因：strm 里的地址指向 115-Desktop 的 **`/d/`（下载路由，恒 302）**，
该直链签名**绑定请求方 User-Agent**；Emby 取链与取流两跳 UA 不一致 → **403**。
修法：全库 strm 的端口 **11500 → 11501**，落到本地中继 `strm-relay`（固定 UA 取链+取流），
已实测 Emby `stream?static=true` → **206 / video/mp4 / ftyp isom**。

不是 Emby 的锅，也不是「本地代理」设置没生效——那个设置**只作用于 `/play/`**，与 strm 走的 `/d/` 无关。

## 二、现在这条链路长什么样

```
播放器 / 手机 / 小欢影视
   └─► Emby（Windows，http://192.168.2.238:8096 或 172.25.224.1:8096）
          └─► 读 G:\srtm\...\xxx.strm
                 └─► http://192.168.2.238:11501/d/<pickcode>/<URL编码文件名>
                        └─► Windows portproxy 11501 ─► WSL  strm_relay（0.0.0.0:11501）
                               └─► 固定 UA 向 http://192.168.2.238:11500 要直链（拿 302）
                                      └─► 跟随到 115 CDN，把字节流回给 Emby / 客户端
```

三条关键事实：

1. **strm 永远走 `/d/`**（115-Desktop 的 `/d/` 恒 302，与 `转发策略` 设置无关）。
2. **`/play/` 才是流式路由**（内置播放器走它，所以"切成本地代理就秒好"）。
3. **中继不看客户端 UA**，所以「全库播放现在唯一依赖 = WSL 里的中继活着」。
